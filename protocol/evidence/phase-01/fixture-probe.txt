## The standing guard
  monti/__init__.py:100 — the only guard. `flask launch` refuses to run when a
  customer carries is_fixture = 1:
    "Fixture rows are still present. Run `flask purge-fixtures` first — "
                "laun..."
  It fires once, at launch, on one table. Nothing refuses a fixture row at write
  time on any table, and 38 of the 45 tables carry no marker at all.
  monti/seed.py writes is_fixture = 1 deliberately; monti/purge.py deletes and
  sweeps orphans. Neither is a guard.

  CHG-003's third gate clause — 'the guard fires on a deliberately reintroduced
  fixture row' — is therefore met only for `flask launch` and only for customers.
  DATAOPS-01 owns SK-38 and calls this gate at Phase 2.
