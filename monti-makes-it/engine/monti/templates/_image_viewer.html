{# The item image viewer — one component, every item type (§10.3, WI-P-03). It is used by the public catalogue, the member portal, the Product Genome and order lines. There is one implementation because four would drift, and a viewer that behaves differently depending on which page opened it is a viewer a member cannot learn once. The requirements that shaped it: mobile-first a thumb, not a mouse. Swipe moves between images, the close control is inside the thumb arc, targets are 44px. zoomable double-tap and pinch, plus +/- for a pointer and a keyboard. annotated a diagram layer with callouts that must stay legible at 320px and must never cover the thing they point at (§10.5), so callouts render outside the subject with a leader line. operable full keyboard: arrows, +/-, 0 to reset, Escape to close. Focus moves into the dialog and returns to the thumbnail that opened it. No focus trap that cannot be escaped. honest an item with no images gets an explicit empty state, not a blank space — a missing viewer on a portal item is a P1. `images` is a list of dicts with caption, source_label, alt_text and either `svg` or `stored_name`, plus optional `annotations` JSON. #} {% macro viewer(images, item_name, viewer_id) %} {% if images %}
