# Charting baseline on the frozen build

## Is there a charting layer?
  static/js files: ['image-viewer.js']
  a chart module:  NONE — no chart module of any kind
  templates drawing marks inline: 4
    monti/templates/_image_viewer.html
    monti/templates/_shell.html
    monti/templates/admin/revenue.html
    monti/templates/base.html

  Every chart is drawn as inline SVG inside its own template. There is no shared
  renderer, so a fill-path or y-domain fix would have to be made per template —
  which §1.4 calls a protocol violation. VIZ-01 builds the layer at Phase 5.

## Share bars (CHG-005) — the same defect as the chart, measured

  Two corrections, both found by QA-01 rather than by me.

  FIRST: a probe searching for class names containing "share" or "bar" reported the
  share bars absent. They are there, called `.meter`, on three templates:
    monti/templates/admin/revenue.html      "Revenue by client" table, Share column
    monti/templates/admin/order_detail.html
    monti/templates/portal/quote_detail.html
  The markup is:
    <div class="meter"><span style="width:{{ ...|round|int }}%"></span></div>

  SECOND, and this is a build defect rather than a probe error: **`.meter` has no rule
  in app.css.** The file defines `.meter-head`, `.meter-head strong`, `.meter-track` and
  `.meter-fill` at lines 270-273 — and NO TEMPLATE USES ANY OF THEM. `.meter-green`
  (admin/order_detail.html:23) is undefined too. Both halves of the contract exist and
  they do not match.

  Measured in Chromium at 1440x1000 against a throwaway seeded database (§1.5's
  explicitly labelled local development seed), so the table had rows to draw:

    .meter        background-color  rgba(0, 0, 0, 0)
    .meter        border-width      0px
    .meter        height            0px
    .meter        bounding box      127 x 0
    .meter > span display           inline        <-- ignores width
    .meter > span inline style      width:100%
    .meter > span bounding box      0 x 0

  The share bar is not illegible. It renders **nothing** — zero pixels, in both themes.
  CHG-005's gate reads "A reader ranks all clients correctly from the bars alone with
  numbers hidden. Track and fill visible in both themes." There is no track and no fill.

  Screenshot chg-005-share-bars.png shows the Share column on seven clients: the
  percentage text and no bar of any kind. The same screenshot shows CHG-010's defect in
  the same table — a filled "Open portal" button repeated on every row.

  This makes CHG-001 and CHG-005 the same defect: a class name in a template that the
  only loaded stylesheet does not define. §8.1 predicted exactly this shape — "DS-01 and
  VIZ-01 doing one job each that closes four items." Filed as D-030.

  An earlier version of this file said "app.css rules: .meter, .meter-track, .meter-fill"
  and ".meter is used on 4 surfaces ... and (as .quota-dot rows) 4 more". Both were
  wrong: `.meter` has no rule, three templates use it, and .quota-dot appears in three
  templates and is not a meter.

## Sparkline (CHG-002) — this one really is absent

  Checked structurally, not by name: no <polyline> and no <path> appears in ANY template
  in the build. The only data marks drawn anywhere are the <rect class="chart-bar">
  elements on admin/revenue.html.

  There is no sparkline in this build. There is also no 30-day window to draw one for:
  analytics.PERIODS offers 1d, 7d, 21d, 45d, 90d, 180d, 365d — no 30d.

  CHG-002 reads "30-day sparkline is sloppy." The surface it describes does not exist
  here. See the note on protocol-versus-build drift in surface-inventory.md.

## ROOT CAUSE — measured in a browser, not inferred

Every class the revenue chart uses is undefined in the only stylesheet the
application loads. Both shells load exactly one: monti/static/css/app.css
(_shell.html:11, base.html:11).

  .chart-wrap    NOT DEFINED in app.css
  .chart-svg     NOT DEFINED
  .chart-grid    NOT DEFINED
  .chart-axis    NOT DEFINED
  .chart-bar     NOT DEFINED
  .range-row     NOT DEFINED
  .range-btn     NOT DEFINED

app.css does carry chart rules — at lines 288-300 — but under a different naming
scheme (.chart, .chart svg, .chart .legend, .chart .swatch, .chart .cap) that
admin/revenue.html never uses.

Computed style, read from Chromium at 1440x900 on GET /admin/revenue:

  rect.chart-bar   fill    rgb(0, 0, 0)      <-- SVG default. Black.
  rect.chart-bar   stroke  none
  .chart-grid line stroke  none              <-- grid invisible
  .range-btn       background  rgba(0,0,0,0) <-- period picker is plain text,
  .range-btn       border-width 0px              0px border, 0px padding
  .range-btn       padding-left 0px
  :root            --green  #1E8F63          <-- brand green is defined and
                                                 reaches nothing on this surface

  bars rendered: 7

So CHG-001 — "Revenue chart renders as solid black block" — is real, and its cause
is a stylesheet naming mismatch, not a fill-path bug. An SVG <rect> with no fill
declared paints black; give the bars real heights and the result is a solid black
block.

This matters for Phase 5. §4.4's VIZ-01 charter diagnoses the defect as "a fill path
closing against the wrong baseline and a y-domain admitting non-numeric values."
That is not what is wrong here. §1.4 says fix the layer — and the layer is the
contract between the renderer and the token set, which is DS-01's Phase 4 output
and VIZ-01's Phase 5 consumer. Filed as D-027.

Screenshots: chg-001-revenue-chart.png (the chart), chg-001-revenue-full.png (the
surface). Taken on the real post-launch dataset: $0.00 revenue, 0 orders, so the
marks are at the zero floor and read as thin black slivers rather than a block.
The fill is the same either way; only the height differs.

## A second defect on the same surface, not in any in-line item

The period picker (1D 7D 21D 45D 90D 180D 365D) renders as unstyled plain text —
no button, no border, no padding, no visible active state. It is a control that
does not look like one. CHG-009 covers its *vocabulary*, not its appearance, and
CHG-013 covers contrast, not missing rules. Filed under §1.9 as an observation,
not built. See D-028.
